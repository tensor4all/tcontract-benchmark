# Agent Workflow

Before acting, read the shared benchmark rules, starting from
`https://github.com/tensor4all/tensor4all-agent-rules/blob/main/rules/benchmark/measurement.md`
(bind yourself off the measured cores, one measurement at a time, a discarded run stays
discarded) and `.../rules/benchmark/index.md` for the rest (evidence, tables). Fallback:
`../tensor4all-agent-rules/rules/benchmark/`. Load only the files your task touches.


## Source of truth for numbers

Tracked result pages live under `result-v2/<campaign>/<profile>/<suite>/<revision>.md`,
one page per measured `(suite, hardware profile, revision)`, and are generated from the
raw run under `data/v2-results/<campaign>/<profile>/<suite>/<timestamp>/`. Do not
duplicate result tables into `README.md` or into docs. The legacy timing-v1 tree
(`result/`, `data/results/`) is frozen history.

`result-v2/<campaign>/INDEX.md` and `HISTORY.md` are generated by
`scripts/v2/gen_index.py <campaign> --write`. Never edit them by hand.

## Every published number carries its revision

A measurement without the commit it was taken at is not evidence. `run.yaml`
records the measured checkout's path, commit, dirty state and features, the
harness commit, the host, the thread environment, the providers and the guard
logs; `scripts/v2/validate_run.py` refuses to accept a manifest whose commit does
not resolve. If you quote a number anywhere, quote its commit with it.

## Timing discipline

One measurement at a time. No concurrent benchmark processes, and no build
while a measurement is running. Every timing goes through the protocol script
of the *measured* checkout (`benchmarks/scripts/pinned.sh`), which pins the
cores and checks they were idle before and after; a run spoiled by other load
is discarded, not published.

Priming is **time-based** (at least 0.5 s of wall time per arm) and identical on
every arm. A fixed call count is not a substitute: after an idle gate this host
reports up to 25% low for the first 1-2 s of sustained work, which is large
enough to be mistaken for a kernel defect.

Correctness precedes timing. `tcbench verify` must report a clean corpus for
every size and thread count before any timing pass; the recorder enforces this
and publishes nothing otherwise.

## Coverage is data, not an apology

The campaign is not run in full on every profile for every commit. A partial run
is legitimate: it is recorded, it is marked `partial` in the index, and it never
displaces a full-coverage report. Do not describe a partial run as if it covered
the suite, and do not infer "no regression" for a population the run did not
contain.
