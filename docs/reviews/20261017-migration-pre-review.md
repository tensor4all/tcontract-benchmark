1. **BLOCKER — The toolkit recorder cannot currently admit these suites, even with valid v2 CSVs.**  
   The plan assumes recording needs only declarations and a small provider-schema change (`docs/migration-to-timing-v2.md:42–48`). However, both suites declare `[plan, packed, tblis]`, not a BLAS vendor arm (`benchmarks/suites/tcbench.yaml:87`; `benchmarks/suites/per-shape.yaml:89`). The toolkit requires a selected vendor even when `vendor_engines(...)` returns an empty list (`../campaign-toolkit/campaign_toolkit/record_run.py:492–503`), then requires `info`’s `vendor.name` to equal it (`:587–595`). Merged tcbench emits `provider`, `provider_version`, `threads`, `threads_effective`, and `tblis`, but **no `vendor.name`** (`../tcontract-rs-work-v2/benchmarks/benchmarks/tcbench/report.rs:466–475`).
   
   The minimal correct contract needs a no-BLAS-vendor recording path, with TBLIS recorded as an external provider—not falsely classified as a mutually exclusive BLAS vendor. That path must also omit an absent `vendor` block or permit null: `vendor_block` returns `None`, the recorder unconditionally serializes it, and the schema accepts only an object (`../campaign-toolkit/campaign_toolkit/record_run.py:378–381,689`; `../campaign-toolkit/schemas/benchmark-run.schema.json:133–140`). Faer and tlinalg’s vendor-backed configurations do not establish compatibility with this campaign.

2. **BLOCKER — Lukbench’s prerequisite migration is omitted, so “the harness side is already done” is false for half the deliverable.**  
   That claim and the proposed common pin appear at `docs/migration-to-timing-v2.md:4–5,49–51`. Lukbench currently ignores unknown options, lacks the toolkit’s selection/rotation/statistic flags, and only warns about unavailable engines (`extern/tcontract-rs/benchmarks/benchmarks/lukbench/main.rs:99–143`). Verification produces no census (`.../engines/verify.rs:20–46`); timing retains only best/scatter (`.../engines/mod.rs:165–186`); CSV lacks the v2 identity, samples, status, and thread-budget columns (`.../report.rs:56–60`).
   
   The plan must explicitly schedule a measured-repository change **before** declaration generation and recording: compatible CLI and `info`, complete verify/timed censuses, chronological samples and median aggregates, real execution rotation, budget columns, and fail-closed feature admission. Pin lukbench to the revision containing that work. There is no numerical estimate in this plan to verify, but its ordering materially understates the remaining scope.

3. **BLOCKER — “Declare each case only at its own dtype” is not expressible in the proposed declaration.**  
   The union dtype axis and per-case restriction contradict each other (`docs/migration-to-timing-v2.md:33–39`). `expected_cells` multiplies **every population’s families by the suite-global `run_spec.dtypes`** (`../campaign-toolkit/campaign_toolkit/timing_evidence.py:28–45`). Neither family grouping nor one population per case restricts that product.
   
   Also, the fixed-per-case dtype behavior belongs to **lukbench**, whose selection filters on `p.dtype` (`extern/tcontract-rs/benchmarks/benchmarks/lukbench/main.rs:153–167`); merged tcbench runs every requested supported dtype for every selected case (`../tcontract-rs-work-v2/benchmarks/benchmarks/tcbench/engines/run.rs:83–97`).
   
   Under the minimal, unchanged toolkit grammar, the generator must emit the case families/populations with global `[f64,c64]`, and lukbench’s new census/CSV producer must explicitly emit the **entire rectangular product**, marking wrong-dtype cells skipped for every engine in **both** verification and timing. A suite-level skip summary or silently filtered cases is insufficient: validation compares the census to the whole declared grid, then requires identical timed cells, statuses, and notes (`../campaign-toolkit/campaign_toolkit/timing_evidence.py:79–90,106–113,130–137`). Declaring only native-dtype cells instead requires dtype-separated suites or an explicitly planned toolkit contract change.

4. **BLOCKER — The literal `order: ['']` makes recorded manifests invalid.**  
   The generator is instructed to emit it at `docs/migration-to-timing-v2.md:34`. The recorder copies a declared order axis into `run_spec` (`../campaign-toolkit/campaign_toolkit/record_run.py:491,724–729`), but the run schema requires each order string to have length at least one (`../campaign-toolkit/schemas/benchmark-run.schema.json:538–546`).  
   **Omit `order` entirely** for these orderless suites and manifests. `expected_cells` already supplies the empty identity value when the property is absent (`../campaign-toolkit/campaign_toolkit/timing_evidence.py:33`). No schema relaxation or artificial order axis is necessary.

5. **BLOCKER — Keeping historical pages is not enough; existing manifests are incompatible with the replacement validator and index.**  
   The preservation promise is at `docs/migration-to-timing-v2.md:49–51,67`. Existing evidence uses `tprims`, `sizes_mib`/`fixed_shapes`, and legacy guard fields; for example, `data/results/zen5-cpu/per-shape/20261010T152119Z/run.yaml:8–15` identifies the measured library as `tprims`. The toolkit requires `library` and rejects unknown properties (`../campaign-toolkit/schemas/benchmark-run.schema.json:6–20`). Validation fails at schema checking **before** declaration-drift handling (`../campaign-toolkit/campaign_toolkit/validate_run.py:189–195,222–228`). Its index also directly reads `m["library"]` (`../campaign-toolkit/campaign_toolkit/gen_index.py:151–166`).
   
   Current CI validates every historical manifest (`.github/workflows/ci.yml:35–40`). The plan needs an explicit read-only legacy validation/index route or a compatibility reader, with historical evidence and pages unchanged. Blindly replacing the scripts with toolkit shims will fail the repository gate.

6. **IMPORTANT — Two descriptors in one repository are supported, but descriptor IDs do not create campaign namespaces or select runners automatically.**  
   The split at `docs/migration-to-timing-v2.md:26–30,61–62` is feasible through `CAMPAIGN_DESCRIPTOR` (`../campaign-toolkit/campaign_toolkit/descriptor.py:40–51`), which survives child invocations because they inherit `os.environ` (`:274–289`). The recorder nevertheless selects the binary exclusively from the active descriptor (`../campaign-toolkit/campaign_toolkit/record_run.py:561`), not from `suite_id`.
   
   Actual naming and publication are:
   - raw directory: `data_dir/profile/suite_id/timestamp` (`record_run.py:555–558`);
   - page: `result_dir/profile/suite_id/page_name.md` (`../campaign-toolkit/campaign_toolkit/campaign.py:224–229`);
   - index: `result_dir/INDEX.md`, scanning **all suites in the active `suites_dir`** and their manifests (`descriptor.py:171–173`; `gen_index.py:126–137`);
   - publishing regenerates that index (`../campaign-toolkit/campaign_toolkit/publish_report.py:74`).

   Specify the second descriptor’s path and invocation, suite ownership, and index ownership. For independent campaigns, the minimal existing-toolkit shape is two explicitly selected descriptors with separate suite directories and separate result/index directories, sharing the repository-level admission lock. Alternatively, deliberately share one combined suite/index namespace and route recorder invocations correctly. Merely changing descriptor IDs does neither. The existing union-index command also discovers descriptors by campaign root, not one descriptor per input index, so it cannot automatically distinguish two descriptors beneath the same root (`../campaign-toolkit/campaign_toolkit/union_index.py:36–50,68–73`); a top-level links-only TOC needs no such extension.

7. **IMPORTANT — The size-spec identity works for current tcbench; lukbench has no corresponding declaration contract yet.**  
   There is **no non-`gemm` mismatch to fix** between the two cited implementations: tcbench family `ij-ik-kj` with `n: ["16"]` becomes `(m,n,k)=("16","16","")` in both `expected_cells` and `declared_shape` (`../campaign-toolkit/campaign_toolkit/timing_evidence.py:35–43`; `../tcontract-rs-work-v2/benchmarks/benchmarks/tcbench/report.rs:63–70`). Resolved extents are separately retained (`report.rs:115–125`).
   
   But `per-shape` explicitly has no size axis (`benchmarks/suites/per-shape.yaml:90`), and lukbench currently reports actual/final-step dimensions, not a declared sentinel (`extern/tcontract-rs/benchmarks/benchmarks/lukbench/corpus.rs:104–108`). The plan’s “keeps its declared sentinel” therefore describes nonexistent behavior (`docs/migration-to-timing-v2.md:59–60`). Choose and document the numeric sentinel and echoing semantics for lukbench. Also specify singleton size populations for tcbench: the recorder joins `n` values with commas, while tcbench parses one numeric `--n` (`record_run.py:609`; `tcbench/main.rs:164–173`). Distinct populations need unique regime labels to avoid evidence overwrites (`../campaign-toolkit/campaign_toolkit/declarations.py:36–45`).

8. **IMPORTANT — Freeze the actual suite engine list and a complete rotation cycle, not “at least two” process sets or all provider-map keys.**  
   The plan lists a `blas` engine (`docs/migration-to-timing-v2.md:12–14`), but merged tcbench exposes `plan,packed[,ttgt][,tblis]`; **`blas` is a feature, not an engine row** (`../tcontract-rs-work-v2/benchmarks/benchmarks/tcbench/engines/run.rs:24–35`). Lukbench exposes only `plan,packed[,tblis]` (`extern/tcontract-rs/benchmarks/benchmarks/lukbench/engines/run.rs:26–31`). Both current suites select three rows.
   
   Validation requires `aa % len(engines) == 0`, so these suites need **3, 6, … process sets**, not two (`../campaign-toolkit/campaign_toolkit/timing_evidence.py:65–70`). Tcbench’s `--rows` preserves requested order, execution rotates it, and CSV follows the rotated census—including skips—so that part already matches validation (`tcbench/main.rs:278–284,308–315`; `tcbench/report.rs:98–108`). Its budget columns also satisfy the validator’s equality check, including skipped rows (`report.rs:175–177,205–206`; `timing_evidence.py:118–120`). Lukbench’s execution is hard-coded plan→packed→tblis and has no budget columns (`lukbench/engines/run.rs:126–158`; `lukbench/report.rs:58`); passing `--rows` cannot fix that without the prerequisite harness work.

9. **IMPORTANT — Reusing the TBLIS collector requires an ingestion path and provider-selection fix, not just adding two printable fields.**  
   The collector already supplies supported fields `name`, `version`, `commit`, `path`, `note`, plus unsupported **`providers[].tag` and `providers[].sha256`** (`scripts/record_run.py:121–145`). Bundled BLIS revision/configuration/build details currently live in `note`; separate schema fields for them are unnecessary.
   
   The toolkit never invokes this collector: it manufactures every non-vendor provider as “the provider in the measured revision,” with null commit (`../campaign-toolkit/campaign_toolkit/record_run.py:342–362`). Thus TBLIS would lose its external identity and missing-provenance refusal. Plan the minimal collector integration/replacement of that placeholder, preserve the commit admission check, and add optional `tag`/`sha256` to both toolkit schema copies. Printing also needs more than `provider_text`: it currently prints neither field, and the report preferentially selects Cargo dependencies, potentially excluding the TBLIS provider entirely (`../campaign-toolkit/campaign_toolkit/report_run.py:176–185,261–262,325–328`). Print the matching external provider’s recorded identity independently of Cargo dependency provenance.

10. **IMPORTANT — The existing build feature and runtime-loader setup would be lost in a straight toolkit migration.**  
    The old recorder exports suite features as `BENCH_FEATURES` and adds `$TBLIS_ROOT/{lib,lib64}` to `LD_LIBRARY_PATH` (`scripts/record_run.py:53,248–250`). The builder depends on that feature variable (`scripts/build_for_tprims_rev.sh:45–49`). The toolkit exports only `BENCH_VENDOR` for the build (`../campaign-toolkit/campaign_toolkit/record_run.py:213–228`); even descriptor `measured.features` is explicitly unused (`../campaign-toolkit/schemas/campaign.schema.json:82–83`). Its suite schema does not accept the old top-level `features` property.
    
    Specify a deterministic campaign build invocation supplying `BENCH_FEATURES=tblis`, and preserve loader setup or establish an equivalent link-time runtime path. Otherwise `--rows ...tblis` fails admission, or the built executable cannot load. These are existing campaign requirements to preserve, not reasons for a new general configuration framework.

Verdict: change the plan (add lukbench’s prerequisite v2 migration, no-vendor/external-provider support, a valid rectangular declaration contract, explicit descriptor/index routing, preserved build/loading behavior, and legacy-evidence compatibility).
